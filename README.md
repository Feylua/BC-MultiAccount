# BC Multi-Account Switcher v1.1.5

一个 Tampermonkey 用户脚本：**在一个 Bondage Club 窗口里同时登录多个账号**，随时切换，后台账号保持在线，并统计未读、记录消息、导出聊天记录。

窗口模型很简单：当前标签页是 1 号账号，2..N 号账号跑在同源 iframe 里。同一时刻只显示一个账号，其他账号照常收发消息。

## 1. 功能总览

| 功能 | 说明 |
|---|---|
| 多账号共存 | 一个窗口最多 8 个账号，后台账号保持登录状态 |
| 快速切换 | 点击头像方块，或按 `Alt` + `1..9` |
| 账号状态 | 在线为绿色，未登录/掉线为灰色，当前账号高亮 |
| 未读角标 | 后台账号的聊天、动作、互动、悄悄话、Beep 计数 |
| 后台消息预览 | 工具栏下方的下拉框，显示最近 14 条后台消息 |
| 自动滚动 | 切换账号时聊天栏自动滚到底部 |
| 设置面板 | 可拖动，位置记忆 |
| 自动重连 | 掉线后自动重新登录，凭据只存在内存 |
| 声音控制 | 当前账号与后台账号分别设置：全部声音 / 仅提示音 / 静音 |
| 消息缓存 | IndexedDB 缓存，保留 7 天，默认开启 |
| HTML 导出 | 单文件导出，按收信 Player 分 Tab，支持类型筛选、搜索、比例图 |

## 2. 安装

### 2.1 前置条件

- 浏览器需安装 Tampermonkey（或兼容的用户脚本管理器）。
- 需要运行 Bondage Club，脚本匹配以下地址：

```text
https://*.bondageprojects.elementfx.com/R*/*
https://*.bondage-europe.com/R*/*
https://*.bondageprojects.com/R*/*
https://*.bondage-asia.com/club/R*
http://localhost:*/*
```

### 2.2 安装脚本

1. 打开 Tampermonkey 管理面板；
2. 新建脚本，或直接打开构建产物：

```text
dist/BC-MultiAccount.user.js
```

3. 确认版本号为 `1.1.5`；
4. 打开 Bondage Club 页面刷新。

脚本使用 `@run-at document-start`、`@grant none`，不请求任何额外权限。

### 2.3 升级

用新版本的 `dist/BC-MultiAccount.user.js` 覆盖旧脚本即可。插件的设置与消息缓存都保存在浏览器本地，升级不会清空。

## 3. 界面导览

工具栏默认在页面顶部居中，结构从左到右：

```text
⠿   账号方块1   账号方块2   ...   ＋   ▸/▾   ⚙
```

| 元素 | 作用 |
|---|---|
| `⠿` | 拖动点，按住可移动整个工具栏 |
| 账号方块 | 显示序号、在线状态、角色名、房间名、未读数 |
| `＋` | 添加一个后台账号 |
| `▸ / ▾` | 展开或收起后台消息预览 |
| `⚙` | 打开设置面板 |

每个账号方块：

- 左侧 `×`：关闭该后台窗格（1 号账号是宿主页面，禁止关闭）；
- 中间大按钮：显示账号序号，点击切换；
- 右上角角标：未读数量；
- 下方：角色名与当前房间名。

颜色约定：

| 颜色 | 含义 |
|---|---|
| 绿色边框 | 账号在线 |
| 灰色、半透明 | 未登录或连接断开 |
| 蓝色高亮边框 | 当前显示的账号 |
| 红色角标 | 有悄悄话或 Beep |
| 蓝色角标 | 有聊天/动作类未读 |

## 4. 多账号管理

### 4.1 添加账号

1. 点击 `＋`；
2. 新窗格会立即显示，并在其中出现 Bondage Club 登录界面；
3. 正常输入账号密码登录即可。

每个窗格是一个独立的 BC 实例，拥有自己的登录状态、房间、好友列表和设置。

### 4.2 切换账号

- 点击任意账号方块；
- 或按 `Alt` + 数字键（`1` 到 `9`），主窗口和 iframe 内都有效；
- 切换时聊天栏自动滚到底部，并清空该账号的未读角标。

### 4.3 关闭账号

1. 点击方块左侧的 `×`；
2. 弹出确认框后确认；
3. 该 iframe 被移除，账号退出。

1 号账号是宿主页面，左侧 `×` 处于禁用状态；关闭它等于关闭整个标签页。

### 4.4 数量上限

最多同时存在 8 个账号（含 1 号）。达到上限后点击 `＋` 会提示。

## 5. 未读角标与后台消息

### 5.1 未读统计范围

只有**非当前账号**的消息才计入未读，类型包括：

- Chat（聊天）
- Whisper（悄悄话）
- Action（动作）
- Activity（互动）
- Beep（好友私信）

角标数字超过 99 显示 `99+`。切换到该账号后，未读清零。

### 5.2 后台消息预览

点击工具栏上的 `▸` 展开下拉框：

- 位于工具栏右下，左对齐，宽度 `22em`，最多 14 行；
- 每行格式为 `[房间] 内容`；
- 聊天和悄悄话带说话人，格式为 `[房间] 名字: 内容`；
- Beep 也带说话人，格式为 `[房间] 名字 #编号: 内容`；
- 展开状态会保存在浏览器中，下次打开保持。

### 5.3 消息文本处理

预览与记录中的文本都经过：

1. BC 的 `CommonCensor` 过滤；
2. 丢弃被完全屏蔽的 `¶¶¶`；
3. 清理行首可能出现的日期、时间、消息编号；
4. 动作与互动自动加括号。

正文中的数字不会被误删。

## 6. 设置面板

点击工具栏右下角的 `⚙` 打开 `[设置]`：

- 面板为黑色半透明；
- 右上角 `×` 关闭，点击面板外空白也关闭；
- 按住标题栏可拖动，位置会被记住；

面板内容分三块：

```text

声音
  ├─ 当前账号
  └─ 后台账号
消息缓存和导出
```

## 7. 自动重新连接

设置项：`自动重新连接`，默认开启。

开启后：

- 账号掉线进入 Relog 界面时，插件会自动重新提交登录；
- 主账号与所有后台账号都适用；
- 首次登录成功时会记住凭据，之后掉线可自动重登；
- 连续失败会按 2s / 5s / 15s / 45s 退避重试，最多 5 次；
- 出现 `ErrorDuplicatedLogin`、密码错误、会话过期等情况会停止自动重试；
- 遇到 `ErrorRateLimited` 会暂停所有账号的自动重连约 30~45 秒；
- 手动离开 Relog 界面后也会停止。

安全说明：

- 凭据**只保存在内存**，页面刷新即失效；
- 不写入 `localStorage`，不写入 IndexedDB，不写入磁盘；
- 关闭该开关后不会进行任何自动尝试。

## 8. 声音控制

设置中的“声音”分为两组，各自三选一：

```text
当前账号： ○ 所有声音   ○ 仅提示音   ○ 静音
后台账号： ○ 所有声音   ○ 仅提示音   ○ 静音
```

默认值：

- 当前账号 = 所有声音
- 后台账号 = 静音

三种模式的含义：

| 模式 | 行为 |
|---|---|
| 所有声音 | 完全放行 BC 原有音频 |
| 仅提示音 | 只保留通知提示音（Beep 提示音），物品音效、动作音效、背景音乐静音 |
| 静音 | 全部音频静音 |

切换账号时，当前显示的账号套用“当前账号”设置，其余账号套用“后台账号”设置，并立即同步到所有窗格。

## 9. 消息缓存

位置：设置面板的“消息缓存和导出”。

### 9.1 开关

`缓存聊天消息（默认开启，保留 7 天）`

- 开启：消息异步写入 IndexedDB；
- 关闭：不再写入新缓存，但已有缓存保留；
- 切换开关不会影响当前会话记录。

### 9.2 缓存信息

面板会显示：

- `缓存起始：` 缓存中最早一条消息的时间；
- `缓存大小：` 条数与大致占用空间。

### 9.3 清除缓存

点击 `清除缓存` 并确认后：

- 删除 IndexedDB 中的全部缓存；
- **不会**删除当前会话内存中的记录。

### 9.4 当前会话记录 vs 缓存

| 名称 | 位置 | 生命周期 |
|---|---|---|
| 当前消息记录 | 内存 | 刷新或关闭页面即清空 |
| 缓存 | IndexedDB | 保留 7 天，或手动清除 |

## 10. 导出消息记录

设置面板提供两个入口：

- `导出当前消息记录`：导出本次会话内存中的记录；
- `导出缓存`：从 IndexedDB 读取，可选时间范围。

### 10.1 导出弹窗

| 项目 | 说明 |
|---|---|
| 来源 | 当前会话消息 / 本地消息缓存 |
| 时间范围 | 导出缓存时可选：最近 24 小时（默认）/ 最近 7 天 |
| ☑ 悄悄话 | 是否包含 Whisper |
| ☑ 私聊 | 是否包含 Beep，含自己发出的 |
| ☐ 系统消息 | 是否包含 ServerMessage |

默认勾选：悄悄话、私聊；系统消息默认不勾选。

选择完成后点击 `导出 HTML`，浏览器会下载一个 `BCMA-chat-<时间>.html` 文件。

### 10.2 导出文件的结构

打开导出的 HTML：

```text
标题
摘要：来源 · 范围 · 生成于 YYYY/MM/DD HH:mm:ss · 总条数   [收信 Player 比例图]
搜索框
类型筛选栏：Chat / Action / Whisper / Beep / 系统消息
账号 Tab：全部 / 玩家 #编号 ...
消息行：时间 · [房间] · 名字 #编号 · 类型 · 内容
```

要点：

- **账号 Tab 按“收到这条消息的 Player”分组**，不是按发信人；
- **类型筛选**可独立显示/隐藏，并与 Tab、搜索叠加；隐藏的类型会变暗并加删除线；
- **比例图**位于摘要右侧，每段宽度 = 该 Player 的条数 ÷ 总条数，图例显示名字、条数与百分比；
- 搜索会匹配消息正文、发信人、房间、账号名；
- 全部为本地静态文件，双击即可打开，无需网络。

`Action` 筛选同时包含 `Activity`（互动）消息。

### 10.3 行标记

- 自己发出的聊天/悄悄话：名字后加 `（我）`；
- 自己发出的私聊 Beep：名字显示为 `对方 #编号（我发出）`；
- 悄悄话与普通聊天一样显示房间名。

## 11. Beep 记录规则

插件只为“真正的聊天 Beep”建档，判定条件：

| 条件 | 要求 |
|---|---|
| `BeepType` | 必须为空（`""` / `null` / `undefined`） |
| `Message` | 非空字符串，纯空白不算 |
| `MemberNumber` | 正整数 |
| Reaction | 排除 |

因此：

**会记录**

- 好友列表发送的 Beep（无论是否勾选“包含房间”）；
- `/beep 编号 内容` 命令；
- 自己发出与收到两个方向；
- 没有 `BeepType` 的 JSON 正文。

**不会记录**

- `BeepType: "Message"`；
- `LCPlayerInfo`、`LCTypingStatus` 等 LianChat 控制 Beep；
- `Leash` 等特殊 Beep；
- 请求房间名等控制类 Beep；
- 表情回应（Reaction），收发两个方向都不记录；
- 空正文或纯空白正文。

发出的 Beep 归入发送者自己的 Tab，收到的 Beep 归入接收账号的 Tab。

| 数据 | 存储位置 | 说明 |

## 13. 常见问题

**Q：点击 `＋` 后窗格空白或一直不加载？**
A：某些代理、扩展或站点策略会阻止游戏被 iframe 嵌入。打开浏览器控制台，若出现 `did not report ready` 提示，说明游戏页面被 `X-Frame-Options` / CSP 拒绝嵌入。

**Q：后台账号会掉线吗？**
A：不会。隐藏的 iframe 只是跳过绘制，网络连接与定时器照常运行；掉线时还可用自动重连恢复。

**Q：后台账号为什么没有声音？**
A：默认“后台账号 = 静音”，在设置里改成立即生效。

**Q：未读数字涨得很快？**
A：房间内动作、互动也会计数，属于正常现象。

**Q：导出的记录缺了某些消息？**
A：检查导出弹窗是否勾选了对应类型；悄悄话、私聊默认勾选，系统消息默认不勾选。

**Q：旧缓存里有“未知（旧记录）”？**
A：早期版本记录没有 `playerId`，会归入该分组。清除缓存后不再出现。

**Q：`Alt` + 数字没反应？**
A：快捷键只在 `Alt` + 数字、且没有 `Ctrl` / `Shift` / `Meta` 同时按下时生效；部分系统会占用 `Alt` + 数字，请改用点击切换。

**Q：能同时开超过 8 个账号吗？**
A：不能，上限固定为 8。

**Q：升级后设置还在吗？**
A：在。设置与缓存都在浏览器本地，与脚本文件无关。

## 15. 从源码构建

日常使用只需安装 `dist/BC-MultiAccount.user.js`，以下内容仅供修改源码时参考。

```bash
npm install
npm run build     # 生成 dist/BC-MultiAccount.user.js
npm run watch     # 监听源码变化，内联 sourcemap
npm test          # 运行纯函数测试
```

构建约定：

- 版本号唯一来源是 `package.json` 的 `version`；
- `build.mjs` 通过 esbuild `define` 注入 `__VERSION__`，并把 `userscript.meta.js` 中的 `__VERSION__` 替换为实际版本号；
- `styles.css` 通过 esbuild 的 `text` loader 导入，运行时注入 `<style>`；
- 产物为 IIFE，不依赖页面模块加载器，保持 `@grant none`；
- 交付物始终是单个 `.user.js`，使用者无需构建。

## 16. 源码结构

```text
src/
├─ main.js                 # 入口：区分宿主页面与 iframe
├─ constants.js            # 频道名、hash、版本、上限
├─ protocol.js             # postMessage 消息类型
├─ core/
│  ├─ account-info.js      # 登录/在线/账号/房间信息
│  ├─ async.js             # waitFor 轮询工具
│  ├─ audio.js             # 声音策略
│  ├─ beep.js              # Beep 判定、文本、说话人
│  ├─ chat.js              # 房间名、聊天滚底
│  ├─ display-hook.js      # 安装 ChatRoomRegisterMessageHandler
│  ├─ fullscreen.js        # 退出全屏
│  ├─ input.js             # Alt+数字识别、子帧编号解析
│  ├─ log-batcher.js       # 日志批量上报
│  ├─ log-record.js        # 消息归一化为记录
│  ├─ messages.js          # 分类、清洗、格式化、说话人
│  ├─ mod-sdk.js           # ModSDK hooks
│  └─ reconnect.js         # 自动重连控制器
├─ child/
│  ├─ bridge.js            # 子 iframe postMessage
│  └─ index.js             # 子 iframe 启动、日志、hooks
└─ parent/
   ├─ accounts.js          # 账号增删切换、iframe、配置下发
   ├─ bridge.js            # 父页面消息分发
   ├─ export-html.js       # 单文件 HTML 导出
   ├─ feed.js              # 后台消息队列与 14 行渲染
   ├─ index.js             # 父页面启动与设置协调
   ├─ log-dialog.js        # 导出选项弹窗
   ├─ log-store.js         # IndexedDB 读写
   ├─ logger.js            # 会话记录 + 缓存
   ├─ settings.js          # 设置读取/保存/规范化
   ├─ settings-dialog.js   # 可拖动设置面板
   ├─ state.js             # 父页面状态
   ├─ styles.css           # 插件样式
   ├─ toolbar.js           # 工具栏、拖动、齿轮、渲染
   └─ top-hooks.js         # 主账号 hooks
```

主账号与后台账号各自有一套 Hook：主账号走 `parent/top-hooks.js`，后台账号走 `child/index.js`，两者行为保持一致。
